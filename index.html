Let us present the Algotrithm from The Fantastic Potatoes... (drumroll) 🥁

What do we know about the problem?

As the streaming platforms are full of tv series, we can say that it is not the lack of the series that are the problem. The problem is that the content is spread over multiple streaming platforms. Users often struggle to find something that matches their specific preferences, because existing recommendation systems rely heavily on broad categories such as previous seen series or popularity. We also know that switching between platforms to search manually is time consuming and frustrating and this creates a need for a more targeted recommendation approach.

What does the solution look like?

The solution is an algorithm that takes a user’s preferences and compares them with a structured dataset of TV series. Based on this comparison, the algorithm recommends the streaming platform that best matches the user’s criteria. In practice, this looks like a simple input output system: the user selects their preferences, the algorithm processes the dataset and the output is a clear recommendation of where they are most likely to find content they will enjoy. The solution should be fast, transparent and easy to use.

What sort of special cases exist?

Special cases include situations where a user has very niche preferences that only matches with a small amount of series. Multiple platforms offer the same series, meaning the algorithm must be decided based on secondary criteria (e.g., language availability or actors involved). A user selects conflicting preferences (e.g. an actor who only appears in one genre, but the user chooses a different genre). The dataset contains incomplete or inconsistent information, which may affect the accuracy of the recommendation. A user has no strong preferences, meaning the algorithm must fall back on general patterns or default suggestions.

How will I recognize that I have found the solution?

You will recognize the solution when the algorithm constantly produces recommendations that feel relevant and helpful. If users report that the suggested platform contains content they enjoy and that the recommendation saves them time compared to searching manually, the solution is working. Another indicator is that the algorithm handles special cases gracefully and still provides meaningful output. So you know you have found the right solution when the system reduces frustration and increases satisfaction in the process of choosing what to watch.

This led us into the conceptualisation phase:

  • Where do we find the data? We discussed using open databases like IMDb, but also realised we might need to create or curate parts of the dataset ourselves to capture the qualities we care about.
  • What format is the data in? Some sources provide CSV and some information might need to be added manually. We need to understand the structure of each source, which attributes exist, how series are described, and what is missing.
  • Do we need to clean or restructure the data? Yes. We need to remove irrelevant fields, standardise genres, add tags, or create new attributes that reflect the viewer’s experience more accurately.
  • How will the algorithm use the data? This is the core question. We need to anticipate what information the algorithm will need to make meaningful recommendations. This means structuring our dataset so that the algorithm can easily access the relevant attributes like: language, genre or actor.

Our Goal

In short, our conceptualization process began with a simple everyday frustration such as finding a good series. Then it grew into a project about designing a dataset, that turned into a database, that captures what really matters when choosing what to watch. Our goal is to create a structured, meaningful dataset that an algorithm can use to make a recommendation for the platform that best matches their preferences.
