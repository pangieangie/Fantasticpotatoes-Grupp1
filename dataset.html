Dataset

Our dataset was originally designed in one large table containing all information about each TV series. However, we quickly realized that this structure became very difficult to work with, especially when we wanted to ask queries based on specific attributes such as genre, language, actors or platform. According to Dale and Lewis (2019), a well structured database should minimize redundancy and make relationships between data clear, which is why we decided to normalize our dataset.

We first attempted a simple first normal form (1NF) structure, but this resulted in long rows with repeated values and inconsistent attribute groupings. To improve clarity and usability, we divided the dataset into multiple tables: Shows, Genres, Languages, Actors, Platforms, and several mapping tables that connect these entities. This approach follows the principle that each table should represent one type of information, while relationships are handled through join tables. It also makes our data easier to query and to expand.
